# 按通道分行求解器：改进规划（2026-11-16）

对象：`bench_lean/rowsolver.py`（方法名 `rows`）。依据：本分支第一轮结果，以及实验一两阶段方法（切片树 SA + sequence-pair/SOCP）的探索记录：
`项目/our-method/方法说明.md`、`项目/our-method/tuning/RESULTS.md`、`analysis/bench3/summary.txt`，
以及交接里的出入口实验（`io_experiments/`）。

规则照旧：不改实验一的代码和结果；新代码放 `bench_lean/`；每个数字都要有原始文件；仓库公开，不放客户资料。

## 0. 现状

第一版已完成交接 §2 的设计：

- 行沿横向通道。两侧都是通道的区域有两行，共用一个分割变量。
- SOCP 以出入口沿通道网络的距离为目标。
- SA 有三种移动。
- 跨行的 X 级净距和疏散距离作为罚项。
- 每个新的最好解用 `evaluate` 复核，最后返回真实路径成本最低的可行解。

第一轮：11 个算例 × 3 个种子 × 60 秒，同一台电脑（DESKTOP-1KNNHJK），11 个进程并行，rows 和 ref 同时跑。结果在 `results_rows/`，对比表用 `python -m bench_lean.compare bench_lean/results_rows` 生成。

**结论**（以 `results_rows/summary_rows_vs_ref.json` 为准）：

- 两种方法 33 次全部可行。
- 每个算例的平均真实路径成本，rows 都低于参考解法：几何平均 −30.7 %，范围 −45.3 % 到 −6.2 %。
- 合并检验：11 个算例的平均成本，Wilcoxon 符号秩 p = 0.00098。
- 改进最小的是 LA-S-U-s2（−6.2 %）。
- 本地重跑的 ref 种子 0 与云端结果相同（如 LA-S-U-s2 都是 5,741.0），说明 ref 在同样的迭代下结果确定。

**这一轮的三个缺陷，结论要打折扣：**

1. **预算不对等。** 参考解法的初始可行搜索不计时。实测墙钟中位数 67.2 秒，最长 133.7 秒（名义 60 秒），33 次中有 17 次超过 63 秒。rows 最长 59.0 秒。偏差对 ref 有利，所以不改变方向，但正式比较前必须对齐。
2. **3 个种子。** 单个算例上精确 Mann–Whitney 的最小 p 值是 0.1，单算例没有显著性可言。
3. **只有测试集，没有调参集。** 第一版参数是凭经验定的，但之后的任何调参都不能再用这 11 个算例。

## 2. 当前版本的短板

| # | 短板 | 影响 |
|---|---|---|
| W1 | 两行区域只有一个分割变量 s：一个深的部门会让对面整行都变浅 | 大部门只能去单行区域或独占一个区域，可行状态变少（SA 里约 40 % 的移动被容量或 SOCP 拒绝） |
| W2 | 行只沿横向通道。部门不能朝竖向主通道 A1 开口，区域两端的空间浪费 | 布局挤在 A1 两侧（见 LA-M-I-BF-s4 的图）；靠墙一侧、区域中间的空地用不上 |
| W3 | 部门之间不能留“对穿”通道，区域中间的空地没有用 | 与 W1 一起限制了大部门的摆放 |
| W4 | 代理目标只走一个竖向连接通道，不算空地上的近路，也不算检查器自己选出入口边 | 代理和真实成本有偏差（例：LA-L-L-s3 10 秒，代理 25,788，真实 24,277），相关性没量过 |
| W5 | 每次移动都重解整个 SOCP：L 规模约 70 次/秒，S 规模约 450 次/秒 | 60 秒里大算例只有几千次评估 |
| W6 | 移动是均匀随机的，没有偏向有物流关系的部门，也没有避开已满的行 | 大量移动被拒绝 |
| W7 | 运行记录只存矩形和检查结果（`baseline.py` 丢掉了迭代数、行状态） | 无法诊断，也无法复现 |
| W8 | 检查器不看柱网：每个算例都有柱位，`evaluate.py` 不检查 | 不是求解器的问题，但关系到“真实要素”的完整性，要和数据负责人确认 |

## 3. 改进项

每项写：做什么 / 为什么 / 怎么算有用。“有用”一律在调参集上判断：10 个种子、按种子配对、Wilcoxon p < 0.05，并且平均改进 ≥ 1 %（结构性改动要求 ≥ 2 %）。

### A. 先让实验可信（其他项都排在它后面）

- **A1 运行记录。**
  - 做什么：`solve` 的统计（迭代数、SOCP 可行率、接受率、代理成本、行状态）和参数、代码提交号都写进结果 JSON。
  - 为什么：L10、W7。
- **A2 调参集。**
  - 做什么：用 `generate.py` 换种子生成 9 个调参算例（3 种规模 × 3 种形态，另加 2 个改造项目，种子与测试集不重叠），放在 `instances_tune/`。测试集 11 个算例只在最后用。
  - 为什么：L3。
- **A3 预算对齐。**
  - 做什么：ref 的初始可行搜索计入预算（或者按 ref 的实际墙钟给 rows 同样的时间），所有方法的墙钟写进对比表，超过 5 % 的运行标出来。
  - 为什么：L5，以及 §0 的缺陷 1。
- **A4 种子与检验。**
  - 做什么：正式实验 10 个种子。单算例用 Mann–Whitney；合并用 11 个算例平均成本的 Wilcoxon，再加按种子配对的符号检验。
  - 为什么：L4。
- **A5 基线补强。**
  - (a) ref 给 300 秒，看它的上限。
  - (b) “经典解 + 合法化”：经典两阶段解（`classic`）的相对位置 → 行的初始解 → SOCP。用来回答“先忽略真实要素再修，和一开始就考虑，差多少”。
  - (c) 可选：Konak FBS MIP 改成固定行，只在 S 规模上跑，做最优性 / 下界参照。实验一的 MIP 在 n ≥ 20、300 秒内找不到解，所以只当参照，不当主线。
- **A6 代理–真实一致性诊断。**
  - 做什么：沿一次 SA 轨迹抽 500 个可行布局，算代理成本和 `evaluate` 真实路径成本的 Spearman 相关和偏差分布，并按算例、按形态（I/U/L）分开看。
  - 为什么：L8、W4；它决定 C1、C2 的优先级。
- **A7 时间曲线。**
  - 做什么：rows 在调参集上分别跑 10 / 60 / 300 / 600 秒。
  - 为什么：L6；它决定 D 组值不值得做。

### B. 表示能力（行表示摆不出的布局）

- **B1 两行改成成对关系（主项）。**
  - 做什么：每对“下行 i、上行 j”由 SA 选一种关系：叠放（d_i + d_j ≤ 区域深度）、i 在 j 左（x_i + w_i ≤ x_j）、或 j 在 i 左，相当于两行之间的 sequence-pair。约束仍是线性，SOCP 仍是凸的。
  - 为什么：W1、W3，以及 L2；实验一里 sequence-pair 正是补切片树短板的那一步。
  - 有用的标准：调参集平均 ≥ 2 %，或 SOCP 可行率明显提高。
- **B2 贯通部门。**
  - 做什么：部门占满区域深度，两侧都开口。这是 B1 的特例（与对面行的所有部门都不叠放），B1 做完就有。
  - 有用的标准：主要看大部门（总装线、包装、库房）摆放后的成本。
- **B3 沿竖向通道的行。**
  - 做什么：区域两端各留一段，沿 A1 排列，朝 A1 开口；角上和横向行的冲突用“区域两端预留长度”这个变量处理。
  - 为什么：W2。
  - 什么时候做：在 B1 之后，看 A6 / A7 的结果再定。
- **B4 柱网。**
  - 做什么：先和数据负责人确认柱子是否算硬约束（线体、大设备不能压柱）。是的话，先改检查器，求解器里把柱位作为行内禁区（x 区间）加进约束。
  - 为什么：W8。

### C. 目标函数和核算一致

- **C1 真实路径收尾。**
  - 做什么：最后 15–20 % 的时间改用真实路径打分的局部搜索（交换、移行），用真实成本接受。`evaluate` 一次 14–114 ms 太慢，要做一个只算路径的快速版，可以参考 `io_experiments/m2fast.py`（那个在经典算例上一次 6–16 ms）。
  - 为什么：L8；E1 显示按真实路径搜索的收益远大于按形心搜索。
- **C2 改代理。**
  - 做什么：每对物流按当前 x 选连接通道（现在按行中心选，只算一次）；连接通道加上区域两端的空地近路。
  - 什么时候做：A6 的相关性低于 0.9 才做。
- **C3 出入口漏洞检查。**
  - 做什么：构造“行两侧隔着通道正对”和“同一行相邻”的布局，确认 `evaluate` 不会给出 0 距离；如果会，按交接加“出入口最小间距”规则，并在 `test_evaluate.py` 里加一项。
  - 为什么：L9。

### D. 搜索效率（A7 显示 60 → 300 秒能好 ≥ 3 % 才做）

- **D1 剖析每次迭代的用时**：容量检查、建矩阵、Clarabel 求解、罚项检查各占多少。
- **D2 两级筛选。** 先固定宽度和深度，只解 x（一维摆放，线性规划，便宜）；有希望的候选再解完整 SOCP。
- **D3 移动偏向。**
  - 做什么：以 0.8 的概率把部门移到物流伙伴所在的行和位置旁边（实验一的 `p_near`、`k_near`）；避开已满的行。
  - 为什么：W6。
  - 注意：实验一 10 个种子没分出 `p_near` 的作用，这里要按 L4 的标准判断。
- **D4 多起点 / 存档。**
  - 做什么：保留最多 10 个不同的行状态，停滞时从存档重启。
  - 为什么：L7。要分规模看，没用就删。
- **D5 温度表。** 在调参集上调；实验一的调参收益只有约 0.3 %，所以放在最后。

### E. 交接 §3 里的其他待办

- **E1′**：交接里的 E1 加“出入口最小间距”后重跑（`io_experiments/e1_run.py`）。
- **E2**：只有 SLP 关系表、没有物流量时，优化结果损失多少。在 bench_lean 上做：用 A/E/I/O/U 换算的权重搜索，用真实物流量核算。
- **E6**：出入口朝向作为 SA 变量。行表示里出入口固定朝通道，这一项和 C1 的检查器选边有重叠，等 C1 做完再看是否还有意义。
- **2×2 消融**：编码 {ref 的分列装箱, rows + SOCP} × 打分 {形心, 通道网络代理}。四格都在调参集上跑，测试集上只跑最终方法和对照。
- **假设参数**：搬运单价、人员单价等 20 个 `ASM` 参数，等有项目数据再替换；替换后要重跑全部结果。

## 6. 不做 / 暂缓

- 不放松 Clarabel 容差（L6：只快 6–14 %，而且会改变可行性判断）。
- 不在测试集上调参（L3）。
- 不声称“沿通道分行”或“SOCP 定尺寸”是新方法（L11）；先把 FBS、DRLP、CAP、Jankovits 2011 对清楚。
- 在 B1 证明有用之前，不做竖向行（B3）。两者都在改表示，一次只改一个才能看清是哪个起作用。

## 7. 风险

- **代理与真实成本不一致（L8）。** 搜得越好的代理，真实成本未必越低。A6 先量；C1 是兜底。
- **B1 让 SA 的搜索空间变大。** 60 秒内可能搜不透，所以要和 A7 的时间曲线一起看。
- **ref 太弱。** ref 只是“证明有解”，赢它说明不了太多。A5 的经典 + 合法化和 ref 300 秒是更有说服力的对照。
- **假设参数（20 个 `ASM`）决定物流和人流的权重比例。** 结论可能随参数变；最终报告要加一组单价敏感性分析（例如人员单价 × 0.5 / × 2）。
